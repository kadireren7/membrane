# GitHub presentation suggestions

Suggestions only — applying them (repo description, topics, social
preview image) requires GitHub UI/API access this tooling doesn't have.
No images are generated here, and no benchmark badges beyond what CI
actually reports (see below) are suggested.

## Suggested repository description

> Research prototype for LLM KV-cache memory: mixed-precision tiering,
> exact sparse retrieval, near-memory/CXL simulation, bit-exact CPU
> quantization, and a synthesizable FPGA datapath — all measured against
> committed, SHA-256-verified artifacts.

(Under GitHub's ~350-character description limit; states scope and
"measured against committed artifacts" up front rather than a marketing
tagline.)

## README badges

Only two badges are used, both verifiable, neither a benchmark claim:

- **CI status** — `https://github.com/kadireren7/membrane/actions/workflows/ci.yml/badge.svg`,
  linking to the actual `.github/workflows/ci.yml` workflow (Debug+ASan
  matrix build/test, plus a separate ThreadSanitizer job). This badge is
  generated by GitHub itself from the real, most recent workflow run —
  it cannot show a fabricated status.
- **License** — a static badge naming the real `LICENSE` file (Apache
  2.0). Not a CI-derived badge, but not a benchmark claim either — a
  fact about a file in the repository.

Explicitly **not** added: coverage badges (no coverage tooling is wired
into CI), a "tests passing" badge separate from the CI badge (would be
redundant and could drift out of sync with the real workflow), or any
badge implying a performance number (e.g. "520,000 tx passing") — those
belong in the README body with their full sourcing (see
[README.md's Key results](../README.md#key-results)), not as an
unqualified badge that strips the context away.

## Social preview text/layout suggestion

GitHub's social preview is a single 1280×640px image shown when the repo
URL is shared. Suggested layout (no image generated here — this is a
content/layout brief for whoever creates it):

```
┌──────────────────────────────────────────────────────────┐
│  MEMBRANE                                                 │
│  Mixed-precision, exact-retrieval LLM KV-cache research    │
│                                                             │
│   [mixed-precision runtime]  [exact sparse retrieval]      │
│   [near-memory/CXL sim]      [bit-exact CPU quant]         │
│   [synthesizable FPGA datapath]                            │
│                                                             │
│  462/462 scenarios · 520,000-tx FPGA cosim · 100,000+-block│
│  quant parity — every number sourced, negative results     │
│  disclosed                                                 │
└──────────────────────────────────────────────────────────┘
```

Design notes for whoever builds the actual image:

- Lead with the five capability tags exactly as worded in README.md's
  opening — do not shorten "exact sparse retrieval" to "sparse
  retrieval" or similar, since the exactness (no approximation in the
  retrieval result) is the specific, load-bearing claim.
- The one-line stat strip at the bottom should only use numbers that
  appear in README.md's "Key results" table, verbatim, so the preview
  image can never drift out of sync with what `scripts/verify-results.py`
  checks. Do not add a number to the preview image that isn't already in
  that table.
- No "production-ready," no rocket/lightning-bolt iconography implying
  real hardware acceleration — this project's own README explicitly
  disclaims that framing (see
  [Technical limitations](../README.md#technical-limitations)).
